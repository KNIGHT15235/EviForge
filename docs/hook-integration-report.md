# EviForge 0.3.0 Hook 集成报告

日期：2026-10-07。代码基线：60b00cf（0.2.0）。

## 已完成

- 默认启用四类 Hook：保护敏感文件、验收要求提醒、轮末变更检查、最终证据报告。TUI 和非交互入口复用配置工厂。
- 增加 `hook_policy.enabled` 开关和 `hook_policy.checks` 项目检查配置；保留已有自定义 Hook。
- 内置文件保护解析实际路径，覆盖符号链接指向的受保护文件；保护执行异常时拒绝工具调用。模板 `.env.example` 等允许正常编辑。被拒绝的写入不会被模型的完成声明改成成功。
- 检查以任务开始的文件内容为基线，覆盖新建、修改、删除文件；检查 Python 语法、可用的 Git whitespace 和显式项目命令。相同内容指纹不重复执行项目检查。
- 项目命令通过 argv 启动，所有配置命令共用 30 秒预算；超时和取消终止并回收子进程。检查过程中源文件变化时标记证据过期。
- 验证失败进入 Agent 上下文；完成阶段最多允许两次修复重试，持续失败返回 failed。未配置项目测试明确标记未验证，不产生全部测试通过的结论。
- 报告在 `.eviforge/hooks/reports/` 原子保存，绑定 session、turn、Agent、cwd、变更内容哈希与检查命令。RunResult.metadata.hook_verification 返回状态和报告位置。
- 增补 HookContext 身份和工具结果字段，以及 main 范围过滤；子 Agent 继承文件保护，默认验收由主 Agent 执行。
- 默认 Hook 保留只读工具并行；自定义工具 Hook 继续保留顺序执行。内存只保留最近 64 个验证上下文，历史报告保留在磁盘。
- 更新配置示例、README、Hook 使用说明、安装包验证和版本/锁文件。

## 保留的边界

文件保护是 WriteFile/EditFile 的应用层规则；Bash/MCP/程序内部副作用仍使用既有权限和计划策略。默认只检查任务后的变更，不将任务前的修改视为已验收。快照排除运行数据、凭证、依赖环境、符号链接文件和构建目录，文件数/大小上限的遗漏明确记录为未验证。

项目测试需要显式配置。partial/no_changes 不等于全部功能通过，passed 只指配置的检查通过。最终报告在正常完成尝试时生成；异常和取消继续由既有 JSONL/RunResult 记录。尚未接入的五个事件不纳入默认配置。

具体配置与报告语义见 [Hook 使用说明](hooks.md)。
